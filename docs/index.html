ロボット評価環境 (Robot Evaluation Environment)

差動二輪の円柱型配膳ロボットを ROS 2 / Gazebo 上で START ラインから GOAL ラインまで走らせ、人とのすれ違い・横切りに対する 移動時間と人との距離を、ブラウザだけで評価・解析するための Docker 環境です。

ROS 2 JazzyGazebo HarmonicDocker Compose DWA / Pure Pursuit / MPC / MPPI / DWPP + 自作Web UI (Starlette + Plotly)
概要 構成図 試行の流れ 動作環境 実行方法 画面の使い方 人の動きの設定 制御器 自作制御器の追加 障害物の認識モード 評価指標 設定ファイル ROS インターフェース 簡易2Dシミュレータ トラブルシューティング ディレクトリ構成

概要

シミュレーション

ROS 2 Jazzy + Gazebo Harmonic。円柱型の差動二輪ロボット (半径 0.25 m, 2D LiDAR) と、速度制御される人モデル 2 体 (数は設定可) を直線の通路に配置。

コース

START ライン → GOAL ラインの一直線。ライン位置はシナリオごとに設定でき、試行ごとに Gazebo 上でも移動します。

人の動き

横切る (交差角・出会い頭タイミング) / 対向 / 同方向 / 静止 / ウェイポイント。開始トリガーとロボット回避反応も設定可能。

制御器

DWA, Pure Pursuit (Regulated), MPC (非線形 MPC), MPPI, DWPP を共通インターフェースで実装。custom_controllers/ に .py を置けば自作も選択可能。

評価

START→GOAL の移動時間、人との最小距離・クリアランス、パーソナルスペース侵入時間、TTC、接触回数、滑らかさ、計算時間など。

ブラウザで完結

評価の開始・停止、ライブ表示、結果一覧、複数試行の比較解析、グラフ (PNG)・CSV・HTML レポート出力まで Web UI から操作。

構成図

sim と eval は同じイメージ (robot-eval:jazzy) から起動する別コンテナで、ホストネットワーク + 共有メモリで DDS / gz-transport 通信します。 既定で ROS_DOMAIN_ID=87, ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST, GZ_PARTITION=robot_eval とし、同じ LAN 上の実機ロボット等と干渉しないようにしています。

試行の流れ

時刻はすべてシミュレーション時刻 (/clock) です。移動時間はロボット中心が START ラインを通過した時刻から GOAL ラインを通過した時刻までを線形補間で求めます (ロボットは START の手前 robot_start_offset から発進し、経路は GOAL の先まで延長しているので、ライン通過時は巡航中)。

実行方法

1. 取得とビルド (初回のみ・十数分)

git clone https://github.com/mamoru1126/robot_evaluation_environment.git
cd robot_evaluation_environment
./scripts/build.sh

2. 起動

./scripts/start.sh

NVIDIA GPU を使う場合 / Gazebo の GUI も出す場合:

./scripts/start.sh --gpu
./scripts/start.sh --gpu --gui

ブラウザで http://localhost:8080 を開きます。右上の Gazebo: 待機 (緑) が表示されれば準備完了です (Gazebo の起動直後は数十秒かかることがあります)。

3. 評価する

  1. 「実行」タブでプリセット (例: crossing_and_head_on) を選び「読込」
  2. 人 1・人 2 の移動方法やタイミングを必要に応じて変更 (ライブビューに予定経路が破線で表示されます)
  3. 障害物の認識モードと、比較したい制御器にチェック。繰り返し回数を設定
  4. 「評価開始」。ライブビューでロボット・人・予測軌道を確認できます。「停止」で中断
  5. 「結果」タブで試行を選んで詳細グラフ、チェックして「解析」タブで比較・PNG/CSV/HTML 出力

./scripts/stop.sh停止 (results/ は残ります)

画面の使い方

実行タブ

  • シミュレータ: Gazebo (ROS 2) か簡易2Dシミュレータを選択。2D は速度 (実時間〜最大) を選べます
  • シナリオ: プリセットの読込・保存・削除。START x / GOAL x / 経路の y、ロボットの開始位置 (START 手前の距離)、GOAL 先の経路延長、タイムアウト、接触したら終了するか、パーソナルスペース / 密接距離のしきい値
  • 人 1 / 人 2: 有効・無効、移動方法、歩行速度、半径、パターン別の位置パラメータ、歩き始めるトリガー、ロボットを避ける反応 (詳細)
  • 認識・制御器: 障害物の認識モード、人の等速予測の有無、LiDAR 点の膨張半径、制御器 (複数選択で比較) と各パラメータ、繰り返し回数、バッチ名
  • ライブビュー: 上から見た通路・START/GOAL・ロボット (青)・人 (橙/青)・軌跡・LiDAR 点・制御器の予測軌道 (緑) と候補軌道、最も近い人までの距離。状態・速度・クリアランス・計算時間・バッチ進捗

結果タブ

バッチごとに試行の一覧 (結果・移動時間・最小距離・最小クリアランス・PS侵入時間・最小TTC・接触回数)。試行をクリックすると、全指標と軌跡 / 人との距離 / 速度のグラフ (Plotly, 拡大・PNG保存可)、 matplotlib の PNG ダウンロードが表示されます。チェックした試行は解析タブで比較できます。

解析タブ

選択した試行を 制御器 / シナリオ / 制御器×シナリオ / 制御器×認識 でグループ化し、平均 ± 標準偏差の表と棒グラフ (表示指標は選択可)、軌跡・クリアランス・速度の重ね描きを表示します。 「比較グラフ PNG」で論文向けの図、「ZIP で出力」で summary.csv, groups.csv, 試行ごとの時系列 CSV, 図 (PNG), report.html をまとめてダウンロードできます。

人の動きの設定

座標系: ロボットは +x 方向に走行。左 = +y、右 = −y。経路は y = course.y の直線です。

パラメータ意味
speed, radius歩行速度 [m/s]、評価用の人の半径 [m] (クリアランス = 中心間距離 − ロボット半径 − 人の半径)
crossing: cross_x, from_side, lateral_start, lateral_end, angle_deg経路を横切る x 位置、出発する側 (left=+y / right=−y)、開始時・終了時の経路からの横距離、交差角
head_on / same_direction: start_x, lateral_offset, travel_distance開始位置、経路からの横ずれ (+ で左)、歩く距離
static: x, y / waypoints: waypoints, loop立っている位置 / 経由点 (先頭が初期位置)、繰り返すか
triggertime: 試行開始から trigger_time 秒後に歩き出す。robot_x: ロボットが trigger_robot_x を越えたら。 encounter (横切り時): ロボットが現在の速度で進むと横切り地点に人と同時に到達するタイミングで歩き出す (encounter_offset 秒だけ人を遅らせる/早める)
reactiveON にすると人がロボットを避ける (Social Force 風の反発)。OFF (既定) は決められた経路を歩き続ける「ロボットに気付かない人」で、最も厳しい条件になります

Gazebo では人は VelocityControl システム (機体座標系の速度指令) で動かし、OdometryPublisher で真値を取得します。人の 3D モデルは脚・胴体・腕・頭で構成され、高さ 0.3 m の LiDAR には 2 本の脚が映ります。

名前内容

制御器

すべて同じ入力 (ロボットの真値姿勢・速度、直線経路、障害物) を受け取り、10 Hz で (v, ω) を出力します。ロボットの物理的な速度・加速度制限は Gazebo の DiffDrive (と 2D シミュレータ) が同じ値で掛けます。 目標速度は既定でどれも 0.8 m/s です。

制御器方式回避主なパラメータ
DWA
dwa		Fox ら (1997) の Dynamic Window Approach。1 制御周期で到達可能な (v, ω) をサンプリングし、3 秒の等速円弧を経路の横ずれ・進捗・方位・障害物との近さ・速度で評価 (DWB 風の評価関数)。衝突する円弧は除外するsim_time, v/w_samples, w_path, w_goal, w_heading, w_obstacle, w_speed, safety_margin
Pure Pursuit
pure_pursuit		Nav2 Regulated Pure Pursuit 相当。速度比例の前方注視点への円弧曲率 κ = 2y/L²、曲率・障害物近接・ゴール接近による減速。前方円弧上に衝突が迫ると停止して待つ (Nav2 では NoValidControl)しない (停止)lookahead_time, min/max_lookahead, regulated_min_radius, cost_scaling_dist, collision_time
DWPP
dwpp		Dynamic Window Pure Pursuit (Ohnishi, arXiv:2601.15006)。Pure Pursuit の曲率直線 ω = κv に対し、速度・加速度制約の Dynamic Window 内で最も近い指令を選ぶ。Nav2 main の dynamic_window_pure_pursuit_functions.hpp を移植 (ROS 2 Jazzy の Nav2 には未収録)しない (停止)Pure Pursuit と同じ (加速度は robot.yaml)
MPC
mpc		非線形 MPC (シングルシューティング, scipy SLSQP, 解析勾配)。ユニサイクルモデルで 20 ステップ × 0.15 s を予測し、経路の横/縦誤差・方位・速度・制御変化と、人/障害物との安全距離のソフト制約を最小化。速度・加速度は制約として扱う。障害物が近いときは直進・右回避・左回避の 3 初期解から最適化するhorizon_steps, dt, q_lateral, q_obstacle, safety_distance, multi_start, pass_side
MPPI
mppi		Model Predictive Path Integral (Williams ら)。時間相関ノイズを加えた 800 本の制御系列をロールアウトし、コストの指数重み付き平均で更新 (Nav2 MPPI 風のコスト)。左右対称な状況で回避方向がぶれないよう、すれ違う側の小さなバイアスありするnum_samples, horizon_steps, temperature, noise_v/w, noise_smoothing, w_*, pass_side
Pure Pursuit / DWPP は経路追従器なので人を避けません。「ロボットを避ける」が OFF の人が経路上に来ると、停止したロボットに人が接触して「接触」で終了することがあります。 これはアルゴリズムの性質どおりの結果です (人を反応させる、または接触しても続行する設定で比較できます)。

人の等速予測は、認識モードが LiDAR + 人追跡 または 真値 のときに DWA / MPC / MPPI / Pure Pursuit 系の衝突判定で使われます (認識モード)。

自作制御器の追加

A. Python プラグイン (推奨・Gazebo / 2D 両対応)

custom_controllers/ に BaseController を継承したクラスを書いた .py を置くだけです。Web UI の「制御器」タブで「再読込」すると一覧に出ます (試行開始のたびに読み直すので、再ビルドも再起動も不要)。PARAMS に書いたパラメータは UI のフォームになります。

from eval_core.controllers.base import BaseController, ControlOutput, Param, rollout_constant


class MyController(BaseController):
    name = "my_controller"                 # 一意な名前
    label = "My controller"                # UI 表示名
    description = "説明"
    PARAMS = {
        "target_speed": Param(0.8, 0.1, 1.5, 0.05, "目標速度 [m/s]"),
    }

    def compute(self, inp):
        st = inp.state                     # t, x, y, yaw, v, w (world 座標の真値)
        s, lateral, _ = inp.path.project(st.x, st.y)
        v = self.p["target_speed"]
        w = -1.5 * lateral
        # inp.obstacles.clearance(xy, tau): ロボット表面から障害物までの距離 (tau 秒後の予測)
        # inp.obstacles.agents: 人 (x, y, vx, vy, radius)  ※追跡/真値モード
        traj, _ = rollout_constant(st.x, st.y, st.yaw, v, w, 1.5, 0.1)
        return ControlOutput(v, w, trajectory=traj.tolist())

完全な例: custom_controllers/example_stop_and_go.py。入力は inp.state, inp.path (project, lookahead_point, heading_at, remaining), inp.obstacles, inp.dt, inp.last_cmd。速度は robot.yaml の上限でクリップされ、Gazebo 側でも加減速制限が掛かります。

障害物の認識モード

モード制御器に渡るもの用途
LiDAR 点群のみ (scan)/scan の点 (world 座標) を静止物として。人の脚も点として見える。点は「LiDAR点の膨張」半径だけ太らせる地図なし・追跡なしのロボット
LiDAR + 人追跡 (scan_tracking, 既定)点群をクラスタリングし、人サイズのクラスタを追跡 (α-β フィルタ) して位置・速度を推定。動いているものは予測付きの人、残りは静止点現実的な脚追跡を持つロボット
真値 (ground_truth)シミュレータの人の位置・速度 + 既知の壁認識誤差を除いたアルゴリズム比較

Gazebo の LiDAR は gpu_lidar (高さ 0.3 m, 360 点, 10 Hz, 12 m) です。OpenGL/EGL が使えない環境では scan_relay が真値から同じ形式の仮想 LiDAR を作ります (起動時のログに表示)。

指標定義

試行開始から GOAL まで [s]制御器が走り出した時刻から GOAL ライン通過まで
平均速度 / 最大速度 / 走行距離(GOAL x − START x) / 移動時間、計測速度の最大値、START〜GOAL 間の軌跡長
最大横ずれ / 横ずれ RMSSTART〜GOAL 間の経路 (y) からのずれ
人との最小距離 (中心間)min ‖probot − phuman‖ (全試行時間・真値)
人との最小クリアランス (表面間)中心間距離 − ロボット半径 − 人の半径。0 以下は接触

同じ試行管理・制御器・指標を、ROS 2 / Gazebo を使わない運動学シミュレータ (DiffDrive と同じ加減速制限、人の脚とレイキャストする 2D LiDAR) で実行できます。 UI のバックエンドで「簡易2Dシミュレータ」を選ぶと、最大速度なら 1 試行 1 秒程度で終わるので、自作制御器のデバッグやパラメータ探索に便利です。最終評価は Gazebo で行ってください。

./scripts/start.sh --2d-only

トラブルシューティング

症状確認・対処
右上が「Gazebo: 未接続」のまま起動直後は Gazebo の起動に数十秒かかります。./scripts/logs.sh sim でエラーを確認。./scripts/diagnose.sh で /clock や /ground_truth/odom のレートを確認。マウスを乗せると不足しているものが表示されます
ログに「VIRTUAL LiDAR」と出るGazebo の gpu_lidar が描画できていません (OpenGL/EGL)。NVIDIA GPU があれば ./scripts/start.sh --gpu。仮想 LiDAR のままでも評価は可能です
実時間より遅い (Real Time Factor < 1)すべてシミュレーション時刻で計測するので結果には影響しませんが、試行に時間がかかります。--gpu の使用や、robot.yaml の LiDAR 点数を減らすと改善します
GUI が出ないecho $DISPLAY を確認し、xhost +local: を実行してから ./scripts/start.sh --gui。Wayland の場合は XWayland が必要です
ホストから ros2 topic が見えない既定で ROS_DOMAIN_ID=87・LOCALHOST 限定です。ホスト側も同じ値を設定するか、./scripts/shell.sh の中で確認してください
results/ のファイルを消せないコンテナが root で書き込むためです。UI の「結果」タブの削除ボタンを使うか sudo rm -r results/<batch>
ビルドで apt の署名エラーベースイメージが古い可能性があります。./scripts/build.sh は --pull で最新の ros:jazzy-ros-base を取得します。./scripts/build.sh --no-cache も試してください
ポート 8080 が使用中./scripts/start.sh --port 8090
